# design-sync notes — beefy-v2

## Ground rules from the user

- **Never commit or push anything in this repo.** Stated explicitly on the first sync
  (2026-08-07). The durable `.design-sync/` files are left in the working tree for the
  user to commit themselves if they choose. Do not offer to open a PR.

## Why this repo needs an unusual setup

beefy-v2 is an **application**, not a component library: no `dist/`, no package exports,
no Storybook, and `node_modules/beefy-v2` does not exist. Three consequences:

- `--entry` must point at a file inside the repo so the converter walks up to the repo's
  own `package.json` (that's what makes `PKG_DIR` the repo root). `.design-sync/entry.ts`
  is that file, generated by `gen-entry.mjs`.
- There is no shipped `.d.ts` tree, so one is emitted into `/types` (gitignored) by
  `npx tsc -p .design-sync/.cache/tsconfig.dts.json`. `findTypesRoot` finds `types/`
  because it is one of the directories it probes. **The emitted `.d.ts` files import with
  `.tsx` extensions** (the repo uses `allowImportingTsExtensions`), which ts-morph cannot
  resolve — they must be stripped afterwards, see "Rebuilding from scratch" below.
- Most of `src/components` is wired to Redux / react-router / i18n. `gen-entry.mjs` keeps
  only components whose transitive relative imports touch none of those (80 of ~117
  candidate exports), then drops internals and app chrome via its `EXCLUDE` set.

## Vite-only features that break under esbuild — all shimmed

`.design-sync/gen-shims.mjs` generates `.design-sync/shims/` and the sync-only path map in
`.design-sync/tsconfig.sync.json` redirects imports there. Three separate problems:

1. **`import.meta.glob`** (13 `src/helpers/*Src.ts` files). esbuild replaces `import.meta`
   with `{}`, so `import_meta.glob(...)` throws at module init and **takes the entire IIFE
   with it — every component dead, `window.BeefyV2` never assigned.** The shims are copies
   of those helpers with the glob calls expanded to static imports.
   - `single-assets` is 27MB / 1379 files. Only the smallest files up to a 1.2MB budget are
     inlined (~620 of them), so uncommon token icons resolve to `undefined`. Raise
     `ASSET_BUDGET` in `gen-shims.mjs` if a needed icon is missing.
   - Only `.svg` and `.png` are inlined — the converter configures no `.webp` loader.
2. **`.svg?react`** (vite-plugin-svgr, 80 icons). esbuild resolves these to data-URL
   *strings*, so `<Icon />` renders as an invalid tag name and paints nothing. The shims are
   real React components written to `<name>.svg?react.tsx` (the `?` is in the filename on
   purpose — the converter's resolver appends `.tsx`).
   - Icons under `images/icons/mui/` must also get the **`mui-svg` class**, mirroring
     `tools/bundle/svgr.ts`. That class is what sizes them (`width/height: 1em` in
     `panda.config.ts`); without it they have only a viewBox and fill their container.
3. **`@repo/styles/*`** → `.cache/styles/*/index.mjs`. The converter's path resolver has no
   `/index.mjs` candidate and its targets must end in `*`, so the alias goes through
   one-line re-export shims in `.design-sync/shims/styles/`.

## Excluded on purpose

`TechLoader`, `FullscreenTechLoader`, `AnimatedButton` — they import `.gif` / `.riv`
assets and the converter configures no loader for those extensions. Re-including them
requires a loader the config cannot set.

## Styling

- CSS comes from `npx panda cssgen`, not from a build artifact — it is regenerated by
  `cfg.buildCmd` on every sync. Because cssgen runs without `NODE_ENV=production`, the
  custom-property names are **unhashed**, which is why `.design-sync/app-surface.css` can
  safely reference `var(--colors-background-body)`. Do not set `NODE_ENV=production` for
  the cssgen step or those names will hash and the appended rules will silently stop
  matching.
- `.design-sync/app-surface.css` puts Beefy's dark surface on `<body>`. The app itself
  applies it on the Layout wrapper (`src/components/Layout/styles.ts`), not on body, so
  without this every generated design would render components on white.
- `cfg.provider` is `BeefySurface` (`.design-sync/preview-provider.tsx`), which wraps each
  **preview card** in `background.content`. The converter's card chrome hardcodes
  `body{background:#fff}` and cannot be configured, and several component backgrounds are
  translucent (`alert.info.background` is `#5c70d623`) with white text — on white they are
  unreadable. `BeefySurface` is a sync artifact, not part of Beefy's own API.

## Known render warns (triaged — not new)

- `[FONT_REMOTE] "DM Sans"` — expected. The app loads DM Sans from Google Fonts via a
  `<link>` in `index.html`; the sync reproduces that as an `@import` at the top of the
  stylesheet. Nothing is self-hosted.
- `[GRID_OVERFLOW]` on `Button` and `ToggleButtons` — resolved with
  `cfg.overrides.<Name>.cardMode = "column"`.
- `tokens: 1 missing` — below the converter's threshold, not chased.

## Finding for the Beefy team (not a sync problem)

`src/components/Form/Input/BaseInput.tsx` — the `status` variant sets `borderColor` for
`error` / `warning` / `success`, but the recipe never sets `borderWidth`, and panda's reset
zeroes it. **All three status states are visually identical in the real app.** The
BaseInput preview deliberately does not include a status cell rather than imply a
difference that does not render.

## Rebuilding from scratch

`cfg.buildCmd` covers panda codegen, cssgen, both generators and the stylesheet
composition. The `.d.ts` emit is **not** in `buildCmd` (it is slow and only changes when
component props change) — run it by hand when props have moved:

```sh
npx tsc -p .design-sync/.cache/tsconfig.dts.json   # exits 1: ~226 errors, all in features/, none in src/components
find types -name '*.d.ts' -exec sed -i '' -E "s/(['\"]\.\.?\/[^'\"]*)\.tsx?(['\"])/\1\2/g" {} +
```

Note `.design-sync/.cache/` is gitignored, so `tsconfig.dts.json` does not survive a fresh
clone — it is 15 lines, recreate it extending `tsconfig.app.json` with
`emitDeclarationOnly`, `declarationDir: ../../types` and `noUnusedLocals: false`.

## Re-sync risks

- **The `.d.ts` tree is stale by default.** Nothing regenerates `/types` automatically, so
  prop changes in `src/components` will not reach the design agent until the tsc step is
  re-run. This is the most likely thing to silently rot.
- **`gen-entry.mjs`'s `EXCLUDE` list is hand-curated** against the component set as of
  2026-08-07. New components appear automatically; new *internals* with generic names
  (another `Item`, `Content`, `Title`) will leak in as cards until added to `EXCLUDE`.
- **The coupling filter is import-based, not behavioural.** A component that gains a Redux
  hook will silently drop out of the synced set on the next sync, with no warning beyond a
  lower component count. Compare against the previous count (80).
- **`ASSET_BUDGET` picks assets by file size**, so which token icons resolve can change as
  images are added or re-optimised.
- 57 of the 80 components still ship the typographic floor card. Previews are authored in
  `.design-sync/previews/` and carry forward across syncs — authoring more is the natural
  incremental improvement on any later run.
